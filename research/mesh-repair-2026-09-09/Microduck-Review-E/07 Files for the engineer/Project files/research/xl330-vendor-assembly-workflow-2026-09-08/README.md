## Supported owning APIs

- `ce-cad/cecad/imported.py:183` — `import_step(path,name,material=...,provenance=...,spec=...,abstracts=...,mass_g=None)`. Requires URL/source and fetched date, verifies supplied file hash, retains all imported shape geometry, attaches drawing-comparison report and provenance. It only requires at least one solid; returning a Part does **not** mean that compound passed topology validation. Do not publish that temporary compound as a validated single Part.
- `cecad/core.py:381` — `Part(name,shape=solid.copy())`, then `assembly_abstraction(description,mass_g=None)`. Wrap each unchanged source solid separately. Copy import provenance, original STEP hash, source entity identity/fingerprint and extraction/transform record into its blueprint. Do not copy an overall import PASS onto a child as if its drawing dimensions were separately verified.
- `cecad/core.py:1598,1699` — `Assembly` and `.add(label,child)`. Parts retain their existing source-relative geometry; an identity placement adds no reconstructed dimensions. Nested assemblies preserve source geometry through their composed placements. Stable labels must be tied to the pinned source/entity or measured fingerprint, not guessed physical component names. Any index selector must refuse a changed STEP/hash/entity inventory.
- `cecad/core.py:3241` — `Assembly.export_step()` emits a compound of leaf shapes. A multiple-solid exported assembly is expected; it must not be fed back into the single-Part validation contract and called a failed manufactured component merely for being an assembly.
- Precedent: `cecad/library/steppers.py:462` imports the PG100 vendor model, checks its drawing report, transforms/splits the source geometry into child Parts, copies import metadata and uses assembly abstractions. XL330 should preserve existing source solids rather than copy PG100's artificial split planes.

## Required constraints for the drawing lane

1. Preserve the original STEP bytes and the full imported compound as reference evidence. Separately account for each of the15solid children and every residual shell/face. Extra surface geometry has no supported closed-Part representation; preserve it as explicitly nonphysical reference geometry, with its role/coverage unresolved. Do not turn it into material, silently omit it from source accounting, or assert complete exterior coverage until its relationship to the solids is measured.
2. Apply the documented vendor-to-local rigid frame exactly once: local(X,Y,Z) = (vendorZ+8,vendorX,vendorY). The15children must preserve all relative locations. Compare source and transformed copies independently: solid inventory, validity/closure, volumes, bounding surfaces, critical bores and STEP round-trip. Copy/placement operations must not fuse solids, refine away source distinctions, thicken surfaces or add bridges.
3. `Part.validate()` at core.py:1442 still requires exactly one valid closed positive-volume solid. The existing aggregate source report is not proof that every selected child passes closure. Explicitly run `check(*children, assembly, verbose=False)` or equivalent individual validity checks plus all assembly gates. **`check(assembly)` alone does not validate child topology**: verify.py:530 validates only explicitly supplied Parts, while its Assembly branch performs interaction/keepout/mobility/drive checks.
4. Run `assembly.check_interference(allow=(),...)` on all105solid pairs and then against the actual neighboring components. Generic `check()` invokes `allow="welds"`; do not manufacture rigid joint declarations to exempt source overlaps. Source interference is a recorded finding requiring interpretation, not permission to edit or fuse the manufacturer's exterior. Unknown internal joints remain undeclared; `add(...,joint=None)` records this explicitly. A static source pose is not proof of real retention, articulation or servo torque path.
5. Keep mass and inertia unknown. Set every child to `assembly_abstraction(...,mass_g=None)`, and describe the parent likewise. **Parent `assembly_abstraction` with no mass alone is insufficient**: `Assembly.mass` falls back to child sums; a child still carrying the default aluminium material would invent density-based mass. `Part.assembly_abstraction` replaces that material with AssemblyMaterial and propagates CANNOT DETERMINE. Never distribute a total servo mass by dummy-solid volume. Any eventual datasheet total belongs once on the exact qualified parent variant/configuration, not on all15children; center of mass and inertia need separate evidence.
6. External mounting/shaft connectors must be re-established on measured source surfaces, retaining original thread/fastener uncertainty and the3mm maximum pilot-depth restriction. Public nominal exterior geometry is not confirmation of the original servo, material, thread profile, internal construction, motion, installed fit or physical acceptance. Existing shelf geometry must not be overwritten merely to get a cleaner drawing.

The limited tool gap is automatic provenance-preserving **multi-body import decomposition and residual-surface accounting**; `import_step` has no assembly-return mode. Existing Part/Assembly APIs can express the candidate in the owning design without core changes, provided the explicit extraction ledger and gates above are implemented. Native STEP product hierarchy/names/materials are not exposed by the present flat `Shape.read` wrapper, so do not claim them recovered.
