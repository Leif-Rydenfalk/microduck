§1Architecture at a glance

Compute

Radxa ZERO 3W — Rockchip RK3566 quad Cortex-A55, Wi-Fi 6 / BT 5.4, 65.000 x 30.000 mm. Runs Armbian; the RK3566's 0.8-TOPS NPU runs a duck detector at 2 Hz, thermal-limited. The store says 1 GB RAM + 32 GB storage and Radxa's own SKU table has no such row — narrowed to two options in ce-parts/radxa-zero-3w.

Actuation

15 x ROBOTIS DYNAMIXEL XL330-M288-T on one 1 Mbps Protocol-2 TTL bus at /dev/ttyS2 (RK3566 UART2_M0). IDs 10-14 / 20-24 / 30-34; mouth = ID 34, excluded from the 14-DoF policy. 270.0 g of the robot's 780 g.

Sensing

Control IMU LSM6DSV16X on the imu_to_dxl board at bus ID 200; an 8x8 ToF that is a VL53L5CX or a VL53L8CX decided at runtime; IMX219 camera behind an M12 lens, mounted inverted; a BMI088 fitted and dormant on the HAT; one mono analog microphone; two NFC antennas whose reader nothing names.

Power

An NP-F550-form-factor 2S Li-ion pack, removable, in a bay measured 38.7310 x 21.1721 x 70.9231 mm. No fuel gauge and no ADC: state of charge is the voltage the servos report. USB-C brings 5 V in; the FUSB302 PD node is disabled and the fitted CC die is an ET7301B.

§5The servo bus

One wire does everything. Fifteen servos and the IMU bridge share a single 3.3 V-logic (5 V-tolerant) TTL half-duplex UART at 1 Mbit/s under DYNAMIXEL Protocol 2.0. There is no second bus and no second port (robotd-design.md).

§6Control-table registers & the tick

Written once at boot (robotd, per servo)

return_delay_time = 0    (vendor default 250 -> 0)
baud_rate        = 3    (1 Mbps)
pwm_slope        = 255
shutdown         = 52   (overload | overheat | electrical shock;
                        vendor default 53, INPUT VOLTAGE ERROR bit cleared)

Rationale (model.rs): the default 250 is 500 us turnaround x 16 devices = 8 ms/tick, 40 % of a 20 ms budget — so it is zeroed. The shutdown byte is the one to read twice: clearing Bit 0 switches off the servo's over-voltage protection, and it has to be switched off because the pack reaches the servos at 6.6-8.2 V against a 6.0 V rating. See §7.

Read every tick / every second

50 Hz loop (20 ms):
  sync_read  regs 124-136  IMU block + 15 servos
             (present pos / vel / load)
  sync_write goal positions
1 Hz slow:
  read regs 144-146  present_input_voltage (0.1 V/LSB),
                     temperature
Gains: P = 200, I = D = 0
  standing_gain_ratio 0.8 - gain_limp 50 on predicted fall

The imu_to_dxl board answers ID 200 in the same sync_read: register block at address 124 carries 6 bytes gyro (int16, 17.5 mdps/LSB) + 6 bytes SFLP game-rotation quaternion (x/y/z as fp16, w reconstructed). One IMU, one code path (imu.rs).

§9The three custom boards

RPI Robot HAT (P1)

65.02 x 30.02 mm (measured off Pollen's mesh)

On the Radxa's 40-pin header. Carries the TLV320AIC3104 codec (0x18), the dormant BMI088, the ToF via a Stemma J5 connector (0x29), the half-duplex bus transceiver, the battery-to-board power path and a 10 kohm I2C pull-up pair (R12/R13). IT MUST ALSO CARRY AN AUDIO POWER AMPLIFIER that no source shows: the codec's recommended minimum load is 16 ohm and its maximum output 30 mW into 16 ohm, against an 8 ohm 2 W transducer.

imu_to_dxl v2 (P2)

unknown — no mesh, no photograph, no drawing

Presents an LSM6DSV16X as a Dynamixel Protocol-2 slave at ID 200, register block 124. Rides the servo bus and takes its power from it. MCU, transceiver and firmware are unpublished. Its connector count is CANNOT DETERMINE and — contrary to what this repo previously argued — is not forced by the bus topology.

unknown
