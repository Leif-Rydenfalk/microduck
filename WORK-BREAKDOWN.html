The critical path, in one sentence 关键路径，一句话

Buy one retail unit (M-1) → trace the three boards off it (B-1) → route them to pass DRC (B-2) → fabricate and assemble them (B-3) → build the first robot from the paper (A-1) → inspect the first five units (Q-1): 18.0 engineer-days of hands-on work in series, and nothing shortens it except adopting Pollen's already-published Apache-2.0 Robot HAT, which removes the largest board from B-1 and B-2. Everything else in this plan runs beside it.

关键路径：购入一台零售整机（M-1）→ 逆向三块电路板（B-1）→ 完成布线并通过 DRC（B-2）→ 投板与贴装（B-3）→ 按文件装配第一台整机（A-1）→ 检验前五台（Q-1）：串行动手工作量 18.0 人天。唯一能缩短它的办法是改用 Pollen 已公开的 Apache-2.0 Robot HAT，从而免去 B-1 与 B-2 中最大的一块板。计划中其余工作均可与之并行。

Vendor lead time is not in that figure: B-3 waits on a PCB house and M-1 waits on a shipment. Those are elapsed days, not engineer-days, and only you can put numbers on them.

上述数字不含供应商周期：B-3 需等待 PCB 厂，M-1 需等待到货。那是日历天而非人天，只有贵方能给出数值。

On effort estimates 关于工时估算

Every day figure in this document is an ESTIMATE and is labelled as one on the parcel. This workshop has never built a physical unit, so it holds no measured time-per-item for any of this work — and that absence is itself measured: 0 units built, 0 of the 44 gated tests ever exercised. What keeps the estimates from being invented is that each one states the arithmetic it rests on: a COUNT we measured (30 print files, 145 M2 holes, 23 cables, 42 end-of-line gates, 22 vendor meshes) multiplied by a per-item rate that is written into the row. Divide our rate out and put yours in — that is what the row is for.

本文件中的每个天数均为估算，并已在各工作包中如实标注。我方从未制造过实物，因此没有任何一项工作的实测单件工时——这一点本身也是实测结论：已制造 0 台，44 项判据测试执行 0 项。估算之所以不是臆测，在于每一条都写明其算式：一个我方实测的数量（30 个打印文件、145 个 M2 孔、23 条线缆、42 项下线判据、22 个供方网格）乘以写在该行中的单件定额。请用贵厂定额替换我方定额。

The largest single estimate, and the least certain, is L-2: 11.0 engineer-days to rebuild 22 vendor meshes as parts we own. The 8 already rebuilt were done by a software agent, not by an engineer, so that rate may be wrong by a factor either way.

最大且最不确定的估算是 L-2：把 22 个供方网格重建为我方自有零件。已完成的 8 个由软件代理而非工程师完成，因此该定额可能显著偏高或偏低。
